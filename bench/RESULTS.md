# Benchmarks: kube-state-metrics (Go) vs kube-state-met.rs (Rust)

Generated by `bench/run.sh` on 2026-11-27, Linux x86_64, Intel(R) Core(TM) i7-1065G7 CPU @ 1.30GHz, 8 CPUs. Notes: the sync time includes process start and the first full list of every resource; the fake API server answers instantly, so it measures kube-state-metrics' own processing. The Go client requests protobuf but the fake server answers JSON, as it does for the Rust client. The CPU column is mostly gzip: both compress at the default level, and Rust spreads it over all cores (lower latency, about the same CPU).

This run covered 1k and 10k pods only: memory on the machine was short (about 3.7 GB free), so 50k was left out. The previous run (before parallel gzip and the curl client) measured 50k pods at sync 1.67x, scrape p50 2.15x, peak RSS 1.70x and CPU 1.78x (Go / Rust). Its gzip column had measured plain scrapes, because `--enable-gzip-encoding` is off by default.
